# 部署说明 v1（本机）

> 配套文档：`README.md`、`docs/需求规格.md`
> 本文只讲**本机（开发机）部署**。云服务器 + Docker 的部署属 Phase 7，**尚未实现**，
> 仓库里的 `docker-compose.yml` / `backend/Dockerfile` 已写好但**未经云上验证**，本文不覆盖。

---

## 1. 前置条件

| 组件 | 说明 |
| --- | --- |
| Python 3.12 | 需要装好三套依赖：主平台 `backend/requirements.txt`、模拟 ERP `mock/erp/requirements.txt`、RPA Worker `rpa/requirements.txt` |
| MySQL 9.x | 本机（brew 装的也行）。**root 无密码是可以的** —— `init_db.sh` 支持直接回车 |
| Redis 8.x | 任务队列，默认 `127.0.0.1:6379` |
| Chromium | RPA Worker 需要。装一次即可：`<解释器> -m playwright install chromium` |

解释器路径不写死在脚本里 —— 起停脚本都从 `.env` 的 `PYTHON_BIN` 读。
本机当前用的是 `/opt/anaconda3/envs/ai-rpa/bin/python`。

## 2. 一次性初始化

```bash
# ① 配置
cp .env.example .env
#   按注释填好 MySQL / Redis / JWT_SECRET / ADMIN_PASSWORD / WORKER_PASSWORD /
#   MOCK_ERP_* 等。PYTHON_BIN 指向装好依赖的解释器。

# ② 建库 + 建表 + 建应用账号（幂等，可重复跑）
MYSQL_ROOT_PASSWORD= ./scripts/init_db.sh

# ③ 创建管理员账号与 RPA Worker 账号（口令读自 .env；幂等）
python scripts/seed_admin.py
python scripts/seed_worker.py

# ④ 装 Chromium（只需一次）
python -m playwright install chromium
```

`init_db.sh` 做两件事：

1. 建两个库 `ai_rpa`（主库）与 `mock_erp`（模拟 ERP 库），并建应用账号、只授权这两个库。
2. 载入 `database/schema/0*.sql` 建表：`001..008` → 主库，`009_mock_erp` → 模拟 ERP 库。

> 表结构以 `database/schema/` 下的文件为准 —— 它们已包含历次迁移的最终形态
> （例如 `005` 已带 `cancel_reason`、`009` 已带 ERP 来源单号唯一键）。
> `database/migrations/` 里的 `010/011` 是给**已经建过表的旧库**做增量升级的，全新初始化不用再跑。
>
> 建表用的是 `CREATE TABLE IF NOT EXISTS`：重复执行不会破坏已有数据，
> 但也**不会**帮你升级已存在的旧表结构。

**root 认证**：`init_db.sh` 优先读环境变量 `MYSQL_ROOT_PASSWORD`（可以是**空串**，表示无密码）；
没设时才隐藏式提示输入。本地 brew 装的 MySQL root 通常无密码，直接回车即可。

## 3. 四个进程

系统由**四个独立进程**组成，各有各的日志与 pid 文件：

| # | 进程 | 启动脚本 | 端口 | 日志 | pid |
| --- | --- | --- | --- | --- | --- |
| ① | 主平台 backend | `./scripts/start.sh` | `8000` | `logs/backend.log` | `logs/backend.pid` |
| ② | 作业进程（僵尸回收） | `./scripts/start_workers.sh` | 无 | `logs/workers.log` | `logs/workers.pid` |
| ③ | 模拟 ERP | `./scripts/start_mock_erp.sh` | `8001` | `logs/mock_erp.log` | `logs/mock_erp.pid` |
| ④ | RPA Worker | `./scripts/run_rpa_worker.sh` | 无 | `logs/rpa_worker.log` | `logs/rpa_worker.pid` |

### 3.1 启动顺序

主平台要先起来：Worker 启动时会**先登录主平台再开浏览器**，连不上会立刻失败退出。
其余三个之间没有严格先后。

```bash
./scripts/start.sh            # ① 主平台
./scripts/start_workers.sh    # ② 僵尸回收
./scripts/start_mock_erp.sh   # ③ 模拟 ERP
./scripts/run_rpa_worker.sh   # ④ RPA Worker（后台）

# 想看着它点浏览器（演示用）：
./scripts/run_rpa_worker.sh --foreground --headed
# 只想让它跑一笔就退：
./scripts/run_rpa_worker.sh --foreground --once
```

每个脚本都支持 `--foreground`（前台跑、Ctrl-C 停，调试用）。
`start.sh` 与 `start_workers.sh` 会**拒绝重复启动**，避免两个进程抢端口/抢任务。

### 3.2 停止

```bash
./scripts/stop.sh     # 一次按顺序停掉上面四个
```

先 `SIGTERM` 给它们机会优雅退出（关连接池、关浏览器），10 秒不走才 `SIGKILL`。
四个一起停是刻意的 —— 喊「停」的时候想要的是「这套东西别跑了」。

## 4. 配置

全部配置集中在根目录 `.env`（样例见 `.env.example`），按用途分组的完整清单见
[`README.md`](../README.md#配置)。几个容易踩的点：

- **`PYTHON_BIN`**：必须指向装好依赖的**绝对路径**。起停脚本都读它，脚本里不写死机器路径。
- **`RPA_API_BASE_URL` 留空即可**：Worker 会按 `APP_HOST`/`APP_PORT` 推导出
  `http://127.0.0.1:8000/api/v1`。Worker 跑在**另一台机器**上时才需要显式填主平台地址。
- **`MOCK_ERP_PAGE_DELAY_MS`**：模拟 ERP 每次 HTML 跳转刻意变慢（默认 1500ms），
  逼 RPA 用「等待元素」而不是「固定 sleep」——故意留的坑，别调成 0。
- **`MOCK_ERP_FAIL_RATE`**：故障注入开关（`0`~`1`）。设成 `1.0` 可复现「重试耗尽 → 转人工」，
  验证完记得改回 `0`。临时验证也可以不改 `.env`，用进程环境变量覆盖（见 §7.5）。

## 5. 健康检查与冒烟

```bash
# 主平台
curl -s http://127.0.0.1:8000/api/v1/health

# 模拟 ERP（它的健康检查不带 /api/v1 前缀）
curl -s http://127.0.0.1:8001/health

# 主平台接口文档
open http://127.0.0.1:8000/docs
```

跑一笔完整的演示（前端未实现，用脚本造订单 + 任务）：

```bash
python scripts/seed_demo_task.py            # 打印 task_id / order_no
# 另开一个终端看着 Worker 领任务并驱动 ERP：
./scripts/run_rpa_worker.sh --foreground --headed
```

验收：管理员 JWT 调 `GET /api/v1/tasks/{id}` 应为 `SUCCESS`，
`GET /api/v1/tasks/{id}/executions` 有执行记录；模拟 ERP 里能按来源单号查到那一笔。

## 6. 测试环境（可选，与开发库物理隔离）

集成测试的前置动作是 `TRUNCATE` 所有表，所以测试跑在**独立的库**上，绝不动开发数据：

| | 开发 | 测试 |
| --- | --- | --- |
| MySQL | `ai_rpa` | `ai_rpa_test` |
| 模拟 ERP | `mock_erp` | `mock_erp_test` |
| Redis | db 0 | db 15 |

```bash
MYSQL_ROOT_PASSWORD= ./scripts/init_test_db.sh    # 建测试库并载入表结构（幂等）
```

`tests/conftest.py` 会在 **import 应用之前**用环境变量把库名顶成测试库，并有
两层保护（配置等值白名单 + 运行时 `SELECT DATABASE()` / Redis `CLIENT INFO` 的 `db=`）
在清库之前拦截 —— 跑测试**不会**动开发数据。

跑测试的命令见 [`README.md`](../README.md#测试)。四套各自独立：
主平台 118、模拟 ERP 93、RPA 单元 63、RPA e2e 2（默认跳过）。

## 7. 常见问题排查

### 7.1 `解释器不存在或不可执行`

`.env` 里的 `PYTHON_BIN` 没填或填错。填成装了依赖的那个解释器的**绝对路径**。

### 7.2 端口被占用

`start.sh` / `start_mock_erp.sh` 启动时会探健康检查，端口被占会直接报错并打印日志末尾。
先 `./scripts/stop.sh`；若还有残留进程，用 `lsof -i :8000` / `lsof -i :8001` 找出来。

### 7.3 MySQL root 认证失败

- **不要**用 `-p` 配合管道喂密码：root 无密码时 `-p` 反而被 MySQL 拒
  （「发一个空密码」和「不发密码」在 MySQL 眼里不是一回事）。脚本已改用 `MYSQL_PWD`。
- 想完全不交互（CI / 无 TTY）：`MYSQL_ROOT_PASSWORD= ./scripts/init_db.sh`
  —— 注意是**设为空串**而不是「不设」，两者在脚本里走的是不同分支。

### 7.4 RPA Worker 起来了又退出

Worker 启动时**先登录主平台、再开浏览器**，平台连不上或口令不对会立刻失败。
看 `logs/rpa_worker.log`：后台脚本的启动探针 grep 的是 `RPA Worker 启动完成，开始领任务`
这一行，它打在**登录成功 + 浏览器开起来之后** —— 探针没命中就是没真正就绪。

### 7.5 想复现「重试耗尽 → 转人工」

不必改 `.env`，用进程环境变量覆盖即可（pydantic-settings 里真实环境变量优先于 `.env`）：

```bash
MOCK_ERP_FAIL_RATE=1.0 ./scripts/start_mock_erp.sh
# 跑 4 次 Worker，期望 4 条 execution 全 FAILED、任务终态 FAILED、订单 FAILED、有一条 TASK_FAILED 通知
./scripts/stop.sh && ./scripts/start_mock_erp.sh   # 改回正常
```

### 7.6 e2e 测试超时

`rpa/tests -m e2e` 的前置是：主平台 + 模拟 ERP 都活着、装了 Chromium，
**且队列里除了刚 seed 的那一笔没有别的待办**。Worker 是 FIFO 领任务、不带过滤条件，
队列里堆着别的任务时它会先干那些，测试最后拿到一个含义不明的超时。
服务没起时 e2e 是 **skip 而不是 fail**（刻意的：忘了起服务不该看起来像代码坏了）。

## 8. 把数据重置回演示前状态

演示前期望的干净状态：主库 7 单全 `IMPORTED`、0 任务 0 执行记录 0 通知；
`mock_erp.erp_orders` 空；Redis 队列空；`backend/var/screenshots/` 空。

```bash
# 停掉四个进程，避免重置时还有 Worker 在写
./scripts/stop.sh

# 清运行期数据（保留 7 条种子订单）
mysql -uroot -e "DELETE FROM ai_rpa.task_executions; DELETE FROM ai_rpa.tasks;
                 DELETE FROM ai_rpa.notifications; DELETE FROM mock_erp.erp_orders;"
redis-cli -n 0 FLUSHDB
rm -f backend/var/screenshots/*

# 需要连订单也重来一遍时，重新执行 init_db.sh 后重跑种子（见数据库设计文档）
```

> 测试产生的数据落在 `ai_rpa_test` / `mock_erp_test` 与 Redis db 15，与上面无关，无需清理。
